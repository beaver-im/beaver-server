# 第 8 章　实施、验证、评审和交接

[返回目录](README.md) · [模块定位](modules/domains.md)

## 8.1 一次任务的顺序

遵循最高原则：开源不运营，无历史包袱，不留任何兼容代码，不计实现成本，有问题直接重构到位，不需要的直接删除（`goctl` 生成边界及授权边界照常遵守）。

1. **定位**：看 AGENTS 和目录，说明目标/允许改动/候选文件/检查；未授权修改则确认，明确直接改的范围内不反复停。
2. **读前保护**：`git status --short`、`git diff --stat`、`git diff --cached --stat`；既有暂存不等于本次操作，发现外部改动不还原。
3. **按需读**：先契约/符号索引，再 logic 与必需依赖/测试。普通任务不全仓重扫，跨域/安全审查可扩大并说明原因。
4. **实施**：先契约，再授权生成，再扩展 logic/svc。生成差异必须能由契约/模板解释，不手修接线蒙混。
5. **验证**：执行已授权且环境具备的检查，逐项记录通过/失败/未运行及原因。不擅自装工具补齐环境。
6. **更新知识**：稳定的边界/入口/命令改主章节；未完进度放交接；方案决策放 ADR。未经请求不为小改写一篇流水账 md。
7. **交接**：目标、改动、验证证据、剩余风险、下一步；用真实相对路径/符号，不复制大段代码或敏感值。

## 8.2 验证矩阵：存在命令，不代表已运行/覆盖完整

| 改动 | 检查与前提 | 能证明 / 不能证明 |
|---|---|---|
| 手册 | 仓根 `powershell -NoProfile -File scripts/check-knowledge.ps1` | 链接、路径、登记命令证据、迁移原文/格式；不是代码合规检查 |
| 所有文本改动 | `git diff --check` 与 `git diff --cached --check`，新增文件另由文档检查覆盖 | 空白错误；不验证业务 |
| HTTP 契约 | 在目标服务 cwd `goctl api validate --api <真实入口>` | 契约解析；不验证鉴权和逻辑语义 |
| 生成变更 | 第 3 章命令（需写入授权、模板/工具前提）+ 人工核对 diff | 契约与接线一致性；本次不生成 |
| 纯单测样例 | 仓根 `go test ./common/convert ./utils/secret`（需授权编译/缓存写入、Go 与依赖齐备） | 仅这两个包；convert 为待清理存量盲映射工具，全仓禁用并可直接移除 |
| 目标业务包 | 先找实际 `_test.go`，再 `go test <目标包路径>` | 不虚构已有测试覆盖；目录无测试就报告并补测试计划 |
| 并发/资源 | 获授权且平台支持时对实际测试包 `go test -race <包>` | 仅触达路径；Windows race 支持/工具链先确认 |
| DB/MQ/跨仓 | 隔离环境/假依赖、显式测试数据/清理授权 | 回滚、重复、超时、断线、越权；不能拿真实环境试跑 |

Go test 会编译、写缓存并可能解析/下载依赖，不是无副作用“只读”；本次没有运行。
仓库存在 [convert_test.go](../common/convert/convert_test.go) 与 [secret_test.go](../utils/secret/secret_test.go)，不表示全仓业务已经有单元测试。
`scripts/stress/` 有 k6 压测/建用户辅助，会产生请求和数据，不属于默认验收。

## 8.3 评审清单（可以逐项回答）

规则正文只在对应主章节，本清单只列检查点；勾选前点进链接核对原文。

- [ ] 无兼容层/双轨/废弃代码残留；受影响调用方已全量同步（原则见 [AGENTS.md](../AGENTS.md)）。
- [ ] 本服务只连自有库；无他服务 DSN、跨库 SQL/JOIN、他域 models；跨服务走接口（[第 6 章](standards/05-data-sync.md)）。
- [ ] 业务归属明确；不跨域 models/DB、不跨仓 RPC；无转发壳与残留文件。
- [ ] 新接口先有 `.api/.proto`；生成命令/cwd/工具版本/模板可追溯；未手造生成物（[第 3 章](standards/02-contracts-codegen.md)）。
- [ ] remote 业务方法 `Api` 后缀、每接口独立 Req/Res、URL/tag 对齐对端、失败不吞（[第 4 章](standards/03-boundaries-remote.md)）。
- [ ] `.api` 按业务类别分组、保护/公开面与中间件匹配、单入口生成（[第 3 章](standards/02-contracts-codegen.md)）。
- [ ] API↔RPC 显式映射；字段与信封同步（[第 4 章](standards/03-boundaries-remote.md)）。
- [ ] 鉴权前缀、公开 group、机器票映射、oauth 单向兼容按[第 5 章](standards/04-runtime-security.md)核对；缺票/伪造头/越权用例验过或注明未验。
- [ ] context/超时贯穿；错误无吞没、对外不泄露内部细节；日志无秘密；并发资源能停止。
- [ ] 事务与消息的失败窗口、幂等/重复、版本与删除同步被考虑；升级方案不依赖默认删库（[第 6 章](standards/05-data-sync.md)）。
- [ ] 实际测试命令与结果可复查，未做项写明；旧报告通过不当作本次通过。
- [ ] 知识更新集中到唯一主章，交接只记录任务状态；他人修改和暂存保留。

## 8.4 文档新鲜度

章节跟着负责业务的变更共同维护，不按“每次 AI 启动”重写。引用路径改名、契约动作变化、生成器/模板更新、子服务合并都是更新触发点。
增加手册文件同时登记 knowledge-checks.json 的 documents；新增重要源码证据/命令也登记。
校验器不访问网络、不执行被登记业务命令，只核对文件/文本；不能把一个存在路径等价于实现已符合所有规范。
没有自动设置 CI、编辑器规则或全局技能；是否自动读入口由各工具能力决定。
