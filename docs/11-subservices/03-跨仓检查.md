# 11.3 跨仓检查

[返回本章](README.md) · [全书目录](../README.md)


1. 子仓同样遵守数据库独占与物理隔离（[第 6 章](../06-data/)）；先确认提供者真实 `.api` 路径、鉴权、字段/信封；调用者的 remote 名称不一定与仓名相同（doc/circle/moment/agent/ai 需逐个核对）。
2. 提供者先改契约生成，实现并验证；调用者更新本仓 types/remote 和 XxxApi 方法，不能引对端模型。
3. 列跨仓同步修改清单（提供方、消费方、机器票/权限与错误语义），各端同步更新；敏感值不入手册。
4. Python Agent 走下章；跨仓不要 etcd RPC/跨库。没读过的子仓细节标未核实，不套用主仓“已达标”。

六个同级子服务仓均已有各自的 `AGENTS.md` 与工程手册，入口见[11.1 工作区](01-工作区.md)。各仓手册登记了本仓真实命令和验证边界；文档检查不等同于业务测试、生成、安全审计或部署。

在线文档还需同时查看 [beaver-desktop-online 手册](../../../beaver-desktop-package/beaver-desktop-online/docs/README.md) 与 [3.3 已知差异](../../../beaver-desktop-package/beaver-desktop-online/docs/03-contracts/03-已知差异与联调检查.md)：当前 block 路由、WS 身份头与只读绑定不能按“已打通”处理。
