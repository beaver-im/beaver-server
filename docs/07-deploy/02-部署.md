# 7.2 部署

[返回本章](README.md) · [全书目录](../README.md)


[Dockerfile](../../Dockerfile) 与 [deploy/](../../deploy/) 是服务部署映射的事实源，
[build/](../../build/) 中有构建、发布、启动相关脚本。`main.go -db` 仅是本地开发建库辅助，既不是总服务启动器，也不是生产共库部署保证。
新增、拆分或下线服务时直接同步更新入口、镜像构建目标、配置结构、服务发现、暴露面、健康检查、资源清理与部署映射，删除失效服务的残留配置。

**危险区分**：`build/build.sh` 会 Docker build/tag/push，`build/all.sh` 会先探测版本是否已发布再批量构建推送，两者都不是只读检查；本次未运行，普通代码阅读/文档检查绝不触发。
仓库当前**没有** `build/check.sh`（已在服务合并与部署目录重整时删除），不要照旧文档虚构一条部署一致性 gate；核对部署映射请直接看 `deploy/<域名>/`、`deploy/config.sh` 的 `SERVICE_DIRS` 与 `build/all.sh` 的模块清单，三者目前分别为域名目录、9 个服务目录与 15 个构建模块，口径不同，改服务时逐项对齐。
未经授权不运行批量启动 bat、Docker、发布、压测或建表命令。
