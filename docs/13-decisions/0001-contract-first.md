# 0001　契约优先的生成边界

状态：本次手册确认的新代码要求（2026-11-22，Asia/Shanghai），不是追溯伪造的历史 ADR。
依据：用户明确要求 go-zero 先写 .api 再工具生成；仓库契约入口和 template 已采用此路径。

决定：HTTP 以 .api、RPC 以 .proto 为源；goctl 生成接线，logic/必要 svc/config 允许业务扩展。
禁止手建等价 handler/routes/types/pb 绕过契约；公共生成行为改模板。
理由：生成源和实际路由/类型可以追踪，避免下一次生成覆盖人工拼装的接线。这是本次决定的理由，不声称原作者当时如此思考。
替代方案：手写全栈接线；本项目不采用，用户明确否定。
后果：契约仍须先于实现，不手写生成物；工具版本与模板缺陷按统一模板修改并全量重生成，记录版本与差异。
边界：网关现有自定义代理不是新业务接口绕过契约的许可；Python Agent 不适用 goctl。
实施细则和证据：[第 3 章](../03-contracts/)。本次没有运行生成。
