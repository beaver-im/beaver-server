# 5.4 错误与日志

[返回本章](README.md) · [全书目录](../README.md)


[response.Response](../../common/response/enter.go) 当前成功 code=0，普通错误 code=1、msg=err.Error()。
**尚未核实统一细分业务错误码登记表**，不要编造 `ErrXXX` API 或宣称已有完整错误体系。
新错误复用本模块真实错误模式，明确给调用方的可见文案；不要把 SQL、内部 URL、凭据或堆栈直接暴露。
若要引入细分码，应先在公共契约处定义并评审消费者，不让各 logic 私造互相冲突数字。

日志沿 [utils/beaverlog](../../utils/beaverlog/logger.go) 与模板：传 ctx、稳定操作名、必要业务 ID；
不要同时多层重复打印同一错误，也不吞错后返回成功；可以补上下文再返回，记录在哪层处理。
禁止把令牌、请求头、完整聊天内容、完整文件内容或未经脱敏配置直接写日志。发现错误直出或敏感日志泄露时直接改掉；目前未全量审计，不标成已合规。

日志 sink 边界：核心仓 `beaverlog` 只写本地 logx/stdout，**不接 MQ、不接 OpenSearch**。日志采集/查询是增值服务，整体拆在独立仓 [`beaver-server-observability`](../../../beaver-server-package/beaver-server-observability/)，本仓保持低配闭环：

- 只有一个索引 `beaver-logs`，服务端与客户端日志同桶，靠文档里的 `source` 字段区分（服务端 `server`；客户端自报 `main`/`render`/`flutter`），这样才能按 `traceId`、`user_id` 把两端日志串起来排查。
- 服务端侧写入：业务进程 stdout → Docker 侧 Vector（配置在独立仓 `docker/vector/vector.yaml`）打 `source=server` → `beaver-logs`。应用不关心日志库是否可用。
- 客户端侧写入：客户端 SDK 批量上报 → 网关（group 段 `log_public` 由 `PublicPatterns` 通用放行）→ 独立仓 `observability_api` 按白名单裁剪字段后写 `beaver-logs`，`source` 用客户端自报值（缺失兜底 `client`）。**本仓不再承接客户端日志上报**：没有 `track` 入口、没有日志 MQ topic、没有日志 consumer。
- “统计/埋点聚合”能力已整体删除，只保留日志本身；不要再往上报契约里加聚合、漏斗、指标字段。

服务端日志只走 Vector，禁止把错误日志写回业务 MQ：那会形成自激环，撑爆内存与队列。本仓连日志 topic 常量都不声明。
