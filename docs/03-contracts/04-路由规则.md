# 3.4 路由规则

[返回本章](README.md) · [全书目录](../README.md)


新业务沿**已核对的六段**：`/{team}/{surface}/{service}/{group}/v1/{action}`。
team 如 beaver；surface 是 api/admin；service 用合并域 account/relation/message/asset/platform 等；
group 用业务、xxx_public、xxx_s2s 或当前契约已有 machine；action 用 snake_case。
禁止新建 `:id` 路径参数，也不要把 `/v1/qrcode_status` 再拆成 `/v1/qrcode/status`。
旧域 auth/user→account、friend/group→relation、file/emoji→asset、chat→message、org/workbench→platform。

**两个 `_public` / `_publish` 不在同一层，必须分清**：[网关 gateway.yaml](../../app/gateway/gateway_api/gateway.yaml) 的 `PublicPatterns` 只匹配 **URL 的 group 段以 `_public` 结尾**（如 `.../auth_public/v1/...`），命中才免外部票；第 3.3 节的 `_publish.api` 只是 `.api` **源文件名**后缀，文件名不会改变网关行为。新增公开接口要两件事同时做对：契约放进公开面文件，URL group 按 `_public` 命名；只做其中一件都不生效。具体鉴权顺序与唯一跨界例外见[第 5 章](../05-runtime/)。

旧 Cursor 入口却说“五段消灭六段”，与旧详细规范和当前路由相反，已记录为被事实纠正的旧句。
旧详细规范要求机器面 `xxx_s2s`，当前部分契约用 `machine`。一旦选定统一命名，直接改契约、重生成并同步所有调用方（本仓/子仓 `remote` 与校验），删除旧路由，**不同时保留两套机器面 group**。
