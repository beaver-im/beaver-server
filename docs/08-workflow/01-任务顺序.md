# 8.1 任务顺序

[返回本章](README.md) · [全书目录](../README.md)


变更策略见 [AGENTS.md](../../AGENTS.md)；本章只写怎么做完一次改动。

1. **定位**：看 AGENTS 和目录，说明目标/允许改动/候选文件/检查；未授权修改则确认，明确直接改的范围内不反复停。产品需求不写入 `docs/`。
2. **读前保护**：`git status --short`、`git diff --stat`、`git diff --cached --stat`；既有暂存不等于本次操作，发现外部改动不还原。
3. **按需读**：先契约/符号索引，再 logic 与必需依赖/测试。普通任务不全仓重扫，跨域/安全审查可扩大并说明原因。
4. **实施**：先契约，再授权生成，再扩展 logic/svc。生成差异必须能由契约/模板解释，不手修接线蒙混。
5. **验证**：执行已授权且环境具备的检查，逐项记录通过/失败/未运行及原因。不擅自装工具补齐环境。
6. **更新知识**：稳定的边界/入口/命令改主章节；方案决策放 ADR。进度在对话交代即可，未经请求不写流水账 md。
7. **收尾说明**：目标、改动、验证证据、剩余风险、下一步；用真实相对路径/符号，不复制大段代码或敏感值。
