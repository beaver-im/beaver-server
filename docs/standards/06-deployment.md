# 第 7 章　配置与部署边界

[返回目录](../README.md) · [下一章：工作流](../workflow.md)

## 7.1 配置结构在哪里，值在哪里

服务配置 Go 结构在各自 internal/config，经 svc 初始化依赖；具体配置文件在各服务 etc 或网关旁。
**数据库隔离配置原则**：生产部署按不同服务器物理隔离各服务数据库（如 `app/account` 独立库、`app/asset` 独立库）。每个业务服务的配置结构只允许持有本域自身的 `Mysql.DataSource` 与最小权限，禁止在配置文件中塞入其他服务的数据库 DSN 或共库账号。
本手册只说明结构与归属，不收录真实数据库、Redis、机器票、对象存储凭据，也不要求 AI 自动打开配置值。
commonconfig 是跨仓地址/RemoteProxy 注册结构，不能误认为可信的公开凭据样本。
新配置：结构/默认值/必填/缺失行为/使用者一起评审；秘密由环境安全注入，日志与任务交接只写变量名。
缺安全关键配置应失败关闭，不能默认用空密钥或开发 token 继续服务。

## 7.2 部署产物不等于单个根程序

[Dockerfile](../../Dockerfile) 与 [deploy/](../../deploy/) 是服务部署映射的事实源，
[build/](../../build/) 中有构建、发布、启动相关脚本。`main.go -db` 仅是本地开发建库辅助，既不是总服务启动器，也不是生产共库部署保证。
新增、拆分或下线服务时直接同步更新入口、镜像构建目标、配置结构、服务发现、暴露面、健康检查、资源清理与部署映射，删除失效服务的残留配置。

**危险区分**：`build/build.sh` 会 Docker build/tag/push；本次未运行，普通代码阅读/文档检查绝不触发。
`build/check.sh` 读取 app/Dockerfile/部署列表并输出比较报告，但其逻辑未以明确失败退出码覆盖所有不一致，不能当作可靠 CI gate。
未经授权不运行批量启动 bat、Docker、发布、压测或建表命令。

## 7.3 独立仓发布契约

独立仓各自配置/部署，不能从主仓 go.mod、模板版本或服务目录推断其发布事实。
跨仓路径或字段变更直接同步修改提供方与全部消费方契约、删除旧路径/旧字段，不保留跨仓兼容层；机器票 audience、签发方、目标地址同时核对结构，不在文档粘贴 secret。
本次只验证六仓入口存在，不承诺所有路由/端口/环境已联通；避免把历史端口表当永恒事实。
